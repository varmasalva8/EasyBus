' ------------------ Security annotations ------------------
note left of AUTH
  Auth Server:
  - OAuth2 / OpenID Connect
  - Issues signed JWTs (RS256)

end note

note right of MESH
  Service Mesh:
  - mTLS for service-to-service traffic
  - Retry, circuit-breaker, traffic shifting
end note

' ------------------ Scaling & Data Strategy notes ------------------
note bottom
  Scaling & Resilience:
  * Use BINARY(16) UUIDs for PKs for distributed systems (UUID_TO_BIN(UUID(),1)).
  * Partition append-only tables (admin_activity_logs, booking_history) monthly/quarterly.
  * Shard Booking DB by geography or tenant for write scale.
  * Read replicas for heavy-read services (Search, Listing).
  * Cache hot data (seat maps, trip availability) in Redis; prewarm on Bus updates.
  * Use Kafka topic partitioning (by tripId) for parallel consumers and ordering where needed.
  * Use idempotent consumers and event deduplication keys.
  * Enforce least-privilege RBAC in Auth Server for Admin operations.
  * Do not store raw card PANs in DB — use tokenization and a vault.
end note
